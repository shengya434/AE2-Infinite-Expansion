# v0.3 设计方案：无限级装配处理器（合成类巨型订单多方块结构）

> 2026-09-03 sensei 需求 · 状态：已定稿核心决策，待开工 · 目标版本 1.3.0

## 0. 定稿决策（sensei）

- **命名**：无限级装配处理器
- **样板来源**：样板槽自持——结构内嵌样板槽 **5×9×200 格**（≈9000 槽，GUI 分页导航）
- **CPU 角色**：待定（独立 CPU vs 自动接管）——默认先做独立 CPU/处理单元，合成终端可选
- **结构形态**：3×3×3 框架 + 核心（沿用集成 CPU 模式）
- **升级卡预留**：批次合成请求处理速度卡 + 处理线程数升级卡

## 1. 背景与痛点

- 现有 CPU/巨型订单体系只完整覆盖**处理类样板**（processing：批量推送/lane/时间片）。
- **合成类样板**（crafting：分子装配室 + 合成树递归）只能下基础订单，巨型订单能力用不上。
- Omni 序列阵列用「整树 1t 全量发送」吃下合成类巨型订单；我们要自己的方案，且性能更优。

## 2. 核心语义：瞬时结算型虚拟合成（sensei 定）

> 合成树整棵展开 → 每个最终产物 X 的基层材料需求算清
> （**网络已有中间产物 → 直接凑数抵扣**；缺的部分折算成基层材料）
> → 从网络**抽取并销毁**基层材料 → **最终产物 X 立即注入网络**

- 中间产物不回网络、不真实装配——「发配即完成」。
- 合成 = 一笔账本结算：材料瞬间蒸发，产物瞬间入账。
- 下单量可达 Long.MAX 级（合成类巨型订单），由**量子 lane 分批**处理（sensei 决策 3）。

### 后续升级卡（sensei 决策 1 预留）
- 批次合成请求处理速度卡（结算吞吐升级）
- 处理线程数升级卡（lane 并行度升级）

## 3. 多方块结构（sensei 决策：3×3×3 框架+核心）

- 形态沿用**集成 CPU 成熟模式**：框架方块（26 个）+ 核心方块（1 个），放地上 3×3×3。
- 复用：框架方块/成型判定/挖取保留成型状态/成型预览（JEI 结构预览已有先例）。
- 核心 = 结算逻辑宿主：网格节点 + pattern 槽（crafting 样板放哪待定，见 §6 开放点）+ 升级卡槽（9 格，容量/速度/线程类）。

## 4. 与 AE2 的集成路径（技术草案）

合成类样板执行链：合成终端下单 → CPU（ExecutingCraftingJob）沿合成树把 inputs 推给
crafting pattern 的 provider（分子装配室）→ 装配室真实合成 → 产物回 CPU crafting storage → 树继续。

本结构要「虚拟结算」，工程上有两条路：

### 路径 A（推荐）：结构 = 特殊 CPU + 兜底 provider
1. 结构接入网络后作为**可选的 crafting CPU** 出现在合成终端 CPU 选择（或自动接管合成类订单）。
2. 订单进入后走**强制展开计划**（参考 extendedae_plus 的 ForcedCraftingPlan +
   ManualWaiting 机制——v0.3 已研究的 CPU mixin 层）：
   - 整树所有中间层当「直接材料需求」一次性折算：网络有中间产物则抵扣，缺的折基层。
   - 基层材料从网络主存储抽取销毁（绕过 crafting storage 中转）。
   - 树全部节点标记完成（manual waiting 状态机清空）→ 根产物 X 注入网络 → 任务完成，
     CPU 存储/任务队列立即释放。
3. 分批：订单量 > 批次阈值 → 量子 lane 分批结算（复用 BatchedCraftingOrder/lane 体系）。

### 路径 B：结构 = 巨型虚拟装配室（pushPattern 拦截）
结构带样板槽，作为 ICraftingProvider 声明可执行其样板；CPU 推 inputs 时结构不装配，
直接上报节点完成并结算产物。实现浅但**合成树多层递归仍需 CPU 等中间产物**——
中间产物要回 crafting storage 才能驱动上层，与「中间产物不回网络」矛盾 → 需 CPU 侧
manual-waiting 配合，最终还是要动 CPU 层。故路径 A 为主，B 的样板槽可作补充入口。

## 5. 分批与线程（复用现有体系）

- 巨型订单分批逻辑（maxBatchCount/并发窗口/翻倍推送）→ 适配到「结算批次」。
- 虚拟 lane 池 / 时间片限流 → 结算批次同样受控，防单 tick 爆炸。
- config：结算吞吐/线程沿用现有 idleLaneTarget/maxConcurrent 语义或新增独立项。
