# 规格：R5b —— 「规则分类列表」也纳入两页共用（存储页 / 收取页）

承接 R5。版本仍 2.0.1。**只在 R5 的页签分派上继续扩展，不碰存储/拒收/导航的既有语义。** 不要自己构建。

## 0. 背景

`Mode2ConfigScreen` 里其实有**三套列表来源**：
1. **存储面板**：`displayItems`/`filteredItems`（元件物品 + 搜索 + 分类过滤）—— R5 已做成两页共用；
2. **规则分类列表**：分类标签行（`tag:xxx` / `mod:xxx`）+ 客户端遍历注册表生成的 `ruleItems`
   （`buildRuleItems(rule)`，与元件存量无关）；
3. 收取集合：`rejectOn ∪ rejectOff`（`RejectListState`）。

sensei 拍板：**②也要纳入两页共用** —— 即"两页都能按分类浏览，并在分类视图里标记"。

## 1. 要改成

### F1 分类标签行两页共用
- 分类标签行（`tag:` / `mod:` 那一条 + 横向滚动）在**两个页签下都显示、都可操作**：
  选中/取消某分类、横向滚动的行为**逐字沿用现有实现**（别重写这套）。
- 当前选中的分类状态**两页共享同一份**（切换页签不重置；重新打开界面时该重置就按现状来，别引入新持久化）。

### F2 分类视图下的列表内容两页一致
- 两页在"选中了某分类"时都显示**同一份** `ruleItems`（客户端生成的全量物品，含黑名单标记）。
- 收取页在这份列表上**额外**并上"显式集合"里、且不在该分类里的条目？
  **不用** —— 分类视图就是分类视图（按分类过滤），
  但**已显式设置的条目在该分类内要显示正确标记**（红「拒」/绿「允」），不能因为"不在元件里"就渲染异常。

### F3 分类视图下的热键按页签隔离（R5 规则的延续）
- **存储页**：分类视图里仍是存储手势（现状：左键切无限 / Shift+左键删除条目 / 右键等，**照现状一字不改**）；
- **收取页**：分类视图里用**收取手势**（左键=切拒↔允、Shift+左键=清除显式设置），
  **不触发**任何存储手势（不切无限、不设阈值、不进黑名单）；
- 两页都要**不误点**：收取页在分类视图里标记时，走的是与物品视图**同一个** packet/方法（别另写一套标记逻辑）。

### F4 提示与标题
- `hint_bar`：分类视图下也要按页签显示对应那一套（存储页那套 / 收取页那套）；
- 列表标题体现"当前是分类视图"（现状怎么写的就沿用，别新造文案；需要新键就走语言键）。

### F5 空/边界
- 该分类下没有任何物品、或元件里一个物品都没有时，两个页签都**不许崩**、不许显示空图标；
- 分类行很长时的横向滚动、以及列表很长的滚动，**沿用现有机制**（别新造滚动）。

## 2. 不许破坏（逐条自检）

1. R5 已定的：两页共用存储面板、收取页并上显式集合（抽空不消失）、`物品`→`存储` 改名、
   配置页「返回」→子模式页、热键隔离、hint_bar 分页显示 —— **一条都不许退化**；
2. R3 死锁修复（拒收条目抽空后仍可见可切回）不许退化；
3. R4 导航语义（重开进配置页、子模式页返回→主模式界面、就地换菜单、`showWorkMode` 走 buffer）不变；
4. 存储页的既有手势与分类视图行为**一字不变**（本轮的存储页只多"分类行在收取页也出现"这件事）；
5. 拒收语义（只拦进不拦出、拒收优先于锁定、物质球内层拒收不吞球、锁定 `return amount`）不动；
6. S11 布局坐标（面板 72..150 / 编辑控件 151..169 / 物品栏 182 / 背包槽 192+ / 快捷栏 250 / `H=276`）不被压；
7. `extract`/insert 路径 0 改动；`Mode2ConfigPacket` 旧 type 不改号（要新 type 就往后加）；
8. 两份 lang JSON 可解析。
